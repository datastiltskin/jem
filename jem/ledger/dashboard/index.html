4 · How each agent actually worked

Reconstructed from the attempts arrays in the run ledgers, not from the agents’ summaries.

Agent 0 — packet locator
  1. Filename globs: *PACKET*, *orchestrator*, classification.py
  2. Content search for “consensus harness”, “SAT anchor”, “Prajna/Agriya”
  3. Git history across all branches
  4. Filesystem-wide .zip search

Four independent strategies, all negative — which is what made the conclusion safe to act on. Handover: back to the user with “not present, please resend” rather than reconstructing the packet from the screenshot.

Agent 1 — orchestrator
  1. Read all 12 packet files before writing anything
  2. Two pre-gates that changed the plan: corpus uses 5 types the classification map lacks; most primary-source domains do not resolve
  3. Apply S → validate.py --strict = 0 on the untouched corpus
  4. Build the liveness gate → run it on the registry → 0/12 pass → discover the India Code migration → harden against soft-404 SPA shells
  5. N refactor (flag 64 generics, write entity_counts.yaml)
  6. Dispatch C ∥ K, then the recount, then report-publication
  7. Verifier rung on staged output (download PDF, extract text, confirm the notification number)
  8. Promote 6 entities; merge 12 report blocks (with two corrections); open PR #31
Agent 2 — Track K (criminal magistracy)
  1. Registry URL indiacode.nic.in/handle/…/20099 — FAIL 404
  2. Migrated host indiacode.gov.in — FAIL soft_404_catch_all_shell
  3. Two guessed bitstream deep links — FAIL 404
  4. Guessed MHA filename 250883_…pdf — PASS liveness, REFUTED on content (it is the penal code, not BNSS)
  5. PRS 297-page PDF — PASS liveness, REFUTED on content (it is the Bill, not the enacted Act)
  6. WebSearch “Act No. 46 of 2023 official gazette” — HIT → MHA 250884_2
  7. curl + pypdf on the VM, read the gazette header — CONFIRMED, 249pp, Act 46 of 2023
  8. Court discovery: POST search_gazette.php for “Judicial Magistrate” (122 issues, mostly noise) → narrow to “Chief Judicial Magistrate” (24 issues) → open three candidate gazettes → read operative text

Attempts 4 and 5 are the run’s best argument for keeping the verifier rung separate from liveness: both URLs are live PDFs on credible hosts, and both are the wrong document. Handover: staging files plus a report naming the four things it refused and why.

Agent 3 — Track C (commercial courts)
  1. POST search_gazette.php “Commercial Court” — 5 issues
  2. Variant queries (“Commercial Courts Act”, etc.) — +1 issue, no new constituting notification
  3. gazette_list_details.php?id=<b64>&date=<b64> reached the 2019 and 2016 issues, which are not in the keyword index — found only by following supersession references inside the 2021 text
  4. Per notification: liveness gate → curl → pypdf extract → read operative text
  5. Verifier: independent re-fetch, literal string check, 13/13 CONFIRM

Step 3 is why this track succeeded where a search-only approach would have stopped at 2021. Handover: 5 entities, a 15-row suggested-edge table, and four decision gates (two of them generalise beyond Tamil Nadu).

Agent 4 — independent recount
  1. Walk data/entities/**/*.yaml with its own Python, skipping schema paths
  2. Extract TYPE_CLASSIFICATION from classification.py via ast — never import the module
  3. Tally the six buckets + generics, record the numbers
  4. Then open entity_counts.yaml and compare
  5. Four extra invariants: arithmetic, unmapped types, generic flag/id consistency, duplicate ids

Handover: one JSONL record written directly to ledger/runs/, verdict PASS.

Agent 5 — report-publication
  1. Locate the entity YAML → read the official site from its sources
  2. Search the body’s publications page
  3. Escalate to parent ministry archive
  4. Escalate to PIB / CAG / Lok Sabha references (N≤3)
  5. Liveness-gate the candidate document; record the trail either way
  6. For the statutory duty, go to the constituting Act’s reporting section

When indiankanoon.org returned 403 it substituted self-hosted regulator copies and disclosed the substitution. Handover: CSV + ready-to-merge blocks + ledger. The orchestrator applied two corrections on merge (see below).
